# 제품화 계획

전체가 완성되면 제품으로 만든다(2026-11-27 결정). 지금은 내 차 한 대에서 검증하는 단계다.

## 방향 (2026-11-27)

1. 먼저 **내 캠핑카에서 아주 높은 완성도**로 만든다. 그 뒤에 판매 작업을 시작한다.
2. **하드웨어는 동작만 하면 된다.** 차별점은 대시보드 등 소프트웨어와 사용자 경험(UX) 품질이다. 기준은 "애플처럼".
3. 판매 경로 1순위는 컴팩스 납품(아래 [판매 경로](#판매-경로)).

## 소프트웨어 구조 (3층)

ESPHome 기본 웹 화면으로는 목표 품질이 안 나온다. 구조를 처음부터 나눈다.

| 층 | 역할 | 선택 |
|---|---|---|
| 보드 펌웨어 | RS485 통신만 담당, 상태와 명령을 깔끔한 내부망 API로 제공 | 개발은 ESPHome으로 시작. API 형태는 처음부터 제품용으로 설계 |
| 화면 | 사용자가 보는 전부 | 1단계: 보드에 올린 웹 앱(홈 화면에 추가). 2단계: 아이폰 네이티브 앱(SwiftUI) |
| 애플 연동 | Siri, 홈 앱, 제어 센터, 잠금 화면 위젯 | HomeKit 지원(ESP32에서 직접 가능) |

네이티브 앱은 앱스토어 등록(애플 개발자 계정, 연 99달러)이 필요하다.

## UX 기준

- **즉각 반응:** 버튼을 누르면 화면이 바로 바뀐다. 패널 실제 상태와 다르면 조용히 되돌린다.
- **설정 없는 첫 연결:** 앱이 블루투스로 보드를 찾아 와이파이를 넘겨준다. IP·비밀번호 입력 화면이 없다.
- **항상 정확한 상태:** 패널에서 직접 눌러도 1초 안에 반영. 끊기면 숨기지 않고 "마지막 확인 3분 전"처럼 보여 준다.
- **인터넷 없이 동작:** 계정·클라우드 없이 차 안 와이파이만으로 전부 된다.
- **한눈에 보는 첫 화면:** 배터리, 물, 켜져 있는 것. 나머지는 한 단계 안쪽.
- **장면:** 도착, 취침, 외출처럼 여러 장치를 한 번에 바꾸는 버튼.
- **위젯과 알림:** 잠금 화면 배터리 잔량, 배터리 부족·문 열림 알림.

시안은 [displays.md](displays.md#대시보드-시안)의 디자인 캔버스를 계속 발전시킨다.

## 소프트웨어 순서

1. 보드 도착 → 통신 분석과 제어 완료(기능 검증)
2. API 형태 확정
3. 웹 앱으로 화면 구성과 흐름 다듬기
4. 네이티브 앱과 HomeKit

## 판매 경로

**1순위: 컴팩스 납품.** 대상 차량이 전부 컴팩스 차량이고, 설치·사후 지원·보증·셰다 프로토콜 문서가 한 번에 풀린다.

| 위험 | 대비 |
|---|---|
| 구매자가 한 곳뿐이라 가격·조건을 컴팩스가 정함 | 다른 제작사의 셰다 패널 차량, 기존 차주 직접 판매 가능성 조사 |
| 시연을 본 뒤 셰다에 직접 앱 기능을 요청할 수 있음 | 따라 하기 어려운 소프트웨어 완성도로 차별화. 시연 전 조건을 문서로 남기기 |
| 납품 수량이 작을 수 있음 | 컴팩스 연간 출고 대수 먼저 파악 |
| 품질 책임과 사후 지원 의무 | 계약에서 책임 범위 정하기 |

협상력: 완성품 시연을 들고 간다, 동호회·카페에서 차주 수요를 확인해 둔다, 납품 형태(완제품 / 대당 로열티 / 개발 용역)를 여러 개 준비한다. 계약과 기술 보호(특허, 비밀유지 약정)는 협의 전에 전문가 확인.

## 개발 중에 챙길 것

- **프로토콜 기록을 재현 가능하게:** 패킷 분석을 남이 따라 할 수 있는 수준으로 [protocol.md](protocol.md)에 적는다. 패널 펌웨어 버전과 제어 박스 날짜(2025-12-15)도 같이 기록한다. 버전마다 프로토콜이 다를 수 있다.
- **개인 값을 코드에 넣지 않기:** 와이파이 이름, IP, 센서 MAC·키는 `secrets.yaml`이나 설정 화면에서 받는다.
- **다른 차량에서 검증:** 같은 패널을 쓰는 다른 유로밴에서도 핀 배치(1=B, 2=A, 3·4·5=GND, 6·7·8=12V)와 패킷이 같은지 확인한다. 지금 결과는 차량 한 대 기준이다.
- **보드가 멈춰도 패널은 정상:** 엿듣기 위주로 설계하고, 보드 고장이 버스를 막지 않는지 시험한다.

## 제품화할 때 결정할 것

| 항목 | 내용 |
|---|---|
| 시장 범위 | Nova-23P(셰다) 패널 차량만 대상. 컴팩스 차량 대수, 같은 패널을 쓰는 다른 제작사 유무가 시장 크기를 정한다 |
| 하드웨어 | Waveshare 보드 + 케이스로 시작, 수량이 늘면 전용 기판. **RJ45 잭과 퓨즈 내장**으로 랜선만 꽂으면 되게 한다 |
| 인증 | 와이파이·블루투스 기기는 국내 판매에 KC 전파 인증 필요. 인증받은 ESP32 모듈을 쓰면 절차가 줄지만 완제품 등록은 따로다. 절차는 인증 대행사에 확인 |
| 소프트웨어 라이선스 | ESPHome은 일부 GPL. 펌웨어를 넣어 팔면 소스 공개 의무가 생길 수 있다. 공개할지, 자체 펌웨어로 갈지 결정 |
| 제조사 관계 | 컴팩스·셰다와 협력하면 프로토콜 문서, 보증, 판매 경로가 풀린다. 협력 없이 가면 패널 펌웨어가 바뀔 때마다 대응해야 한다 |
| 안전과 책임 | 차량 12V 배선 제품 → 퓨즈·절연 기본. 일산화탄소 경보 같은 안전 기능은 제품 기능으로 내세우지 않는다 |
| 사용자 경험 | 첫 설정(와이파이 연결), 무선 펌웨어 업데이트, 접속 비밀번호 |

## 순서

1. 내 차에서 엿듣기와 제어 완성
2. 같은 패널 차량 한두 대에서 시험
3. 컴팩스에 시연, 협력 타진
4. 결과에 따라 인증과 기판 제작
