# 제품화 계획

전체가 완성되면 제품으로 만든다(2026-11-27 결정). 지금은 내 차 한 대에서 검증하는 단계다.

## 개발 중에 챙길 것

- **프로토콜 기록을 재현 가능하게:** 패킷 분석을 남이 따라 할 수 있는 수준으로 [protocol.md](protocol.md)에 적는다. 패널 펌웨어 버전과 제어 박스 날짜(2025-12-15)도 같이 기록한다. 버전마다 프로토콜이 다를 수 있다.
- **개인 값을 코드에 넣지 않기:** 와이파이 이름, IP, 센서 MAC·키는 `secrets.yaml`이나 설정 화면에서 받는다.
- **다른 차량에서 검증:** 같은 패널을 쓰는 다른 유로밴에서도 핀 배치(1=B, 2=A, 3·4·5=GND, 6·7·8=12V)와 패킷이 같은지 확인한다. 지금 결과는 차량 한 대 기준이다.
- **보드가 멈춰도 패널은 정상:** 엿듣기 위주로 설계하고, 보드 고장이 버스를 막지 않는지 시험한다.

## 제품화할 때 결정할 것

| 항목 | 내용 |
|---|---|
| 시장 범위 | Nova-23P(셰다) 패널 차량만 대상. 컴팩스 차량 대수, 같은 패널을 쓰는 다른 제작사 유무가 시장 크기를 정한다 |
| 하드웨어 | Waveshare 보드 + 케이스로 시작, 수량이 늘면 전용 기판. **RJ45 잭과 퓨즈 내장**으로 랜선만 꽂으면 되게 한다 |
| 인증 | 와이파이·블루투스 기기는 국내 판매에 KC 전파 인증 필요. 인증받은 ESP32 모듈을 쓰면 절차가 줄지만 완제품 등록은 따로다. 절차는 인증 대행사에 확인 |
| 소프트웨어 라이선스 | ESPHome은 일부 GPL. 펌웨어를 넣어 팔면 소스 공개 의무가 생길 수 있다. 공개할지, 자체 펌웨어로 갈지 결정 |
| 제조사 관계 | 컴팩스·셰다와 협력하면 프로토콜 문서, 보증, 판매 경로가 풀린다. 협력 없이 가면 패널 펌웨어가 바뀔 때마다 대응해야 한다 |
| 안전과 책임 | 차량 12V 배선 제품 → 퓨즈·절연 기본. 일산화탄소 경보 같은 안전 기능은 제품 기능으로 내세우지 않는다 |
| 사용자 경험 | 첫 설정(와이파이 연결), 무선 펌웨어 업데이트, 접속 비밀번호 |

## 순서

1. 내 차에서 엿듣기와 제어 완성
2. 같은 패널 차량 한두 대에서 시험
3. 컴팩스에 시연, 협력 타진
4. 결과에 따라 인증과 기판 제작
